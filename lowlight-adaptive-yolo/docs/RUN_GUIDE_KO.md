# GitHub 연결부터 실제 실험까지: 처음 시작하는 실행 가이드

이 안내서는 이 ZIP에 들어 있는 `notebooks/START_HERE.ipynb`와 `src/` 코드를 기준으로 작성했습니다. Windows에 Python, Git, CUDA를 설치할 필요가 없습니다. 브라우저에서 GitHub와 Google Colab을 사용합니다.

**처음에는 작은 실험 D가 끝까지 돌아가는 것만 확인합니다. 그다음 본 실험 D·E·M을 실행합니다.** 노트북 전체를 한 번에 실행하지 마세요.

## 1. 오늘 할 일과 전체 흐름

1. 받은 ZIP을 압축 해제합니다.
2. GitHub 저장소를 만들고 코드 폴더를 올립니다.
3. Colab에서 그 저장소의 노트북을 열어 자신의 Drive에 사본을 저장합니다.
4. GPU를 선택하고 GitHub 아이디를 입력합니다.
5. `smoke` 모드로 환경·데이터·입력을 준비한 뒤 D를 2 epoch 학습합니다.
6. 정상 작동하면 `full` 모드로 D·E·M을 학습합니다.
7. 검증 데이터로 기준값을 정하고, 최종 테스트·속도 측정·그래프 생성을 진행합니다.
8. 공개용 결과 ZIP을 GitHub에 올립니다.

역할은 다음과 같습니다.

| 서비스 | 이 프로젝트에서 하는 일 |
|---|---|
| GitHub | 코드와 최종 집계 결과 보관 |
| Google Colab | 코드를 실행하고 GPU로 모델 학습 |
| Google Drive | 원자료 ZIP 백업, 학습 중간 결과와 실험 결과 보관 |

GitHub에 코드를 올린 것만으로 모델이 학습되지는 않습니다. **학습은 Colab의 셀을 실행할 때 시작됩니다.**

## 7. 0단계: 첫 설정과 환경 준비

### 0-1. 자신의 GitHub 아이디 입력

첫 설정 셀에서 다음 부분을 찾습니다.

```python
GITHUB_USER = "YOUR_GITHUB_ID"
REPO_NAME = "lowlight-adaptive-yolo"
MODE = "smoke"
RUN_TAG = "v1"
EPOCHS = 30
BATCH = 16
SEED = 0
```

처음에는 **`YOUR_GITHUB_ID`만 자신의 GitHub 아이디로 바꿉니다.**

예를 들어 GitHub 주소가 `https://github.com/gildong123/lowlight-adaptive-yolo`이면 다음처럼 입력합니다.

```python
GITHUB_USER = "gildong123"
```

이름, 이메일, 전체 GitHub 주소를 넣는 칸이 아닙니다. 저장소 이름을 다르게 만들었다면 `REPO_NAME`도 실제 이름으로 바꿉니다.

| 설정 | 의미 | 처음 사용할 값 |
|---|---|---|
| `MODE` | 작은 작동 확인 / 본 실험 구분 | `"smoke"` |
| `RUN_TAG` | 실험 묶음 이름 | `"v1"` |
| `EPOCHS` | 본 실험의 학습 반복 횟수 | `30` |
| `BATCH` | 한 번에 학습에 사용하는 이미지 수 | `16` |
| `SEED` | 표본 선택·학습의 재현성을 위한 난수 설정 | `0` |

`smoke` 모드에서는 `EPOCHS=30`이라고 써 있어도 자동으로 **2 epoch, 학습 120장, 검증 60장, batch 최대 8**을 사용합니다. 본 실험과 저장 위치도 분리됩니다.

## 8. 1단계: ExDark 데이터 준비와 정답 박스 확인

노트북의 데이터 준비 셀을 실행합니다.

```python
lab.prepare_data()
```

이 셀은 다음 작업을 합니다.

1. Drive에 원자료 ZIP 백업이 있으면 Colab으로 복구합니다.
2. 처음 실행하는 경우 공식 이미지·라벨·분할 정보를 받습니다.
3. 공식 분할을 읽고 이미지와 라벨을 연결합니다.
4. 모든 객체 박스를 YOLO 형식으로 변환합니다.
5. 학습·검증·테스트의 이미지 ID가 중복되지 않는지 확인합니다.
6. 원자료 ZIP을 Drive에 백업합니다.

**`smoke` 모드도 처음에는 원자료 전체를 받습니다.** 작은 표본은 학습 입력을 만들 때 선택합니다. 따라서 첫 다운로드가 작동 확인이라고 해서 아주 작아지는 것은 아닙니다.

정상적인 분할 출력은 다음과 같습니다.

```text
train: 3000
val: 1800
test: 2563
```

이 코드에서는 이미지나 라벨이 없으면 임의로 빼고 계속 진행하지 않습니다. 누락·중복·잘못된 좌표를 발견하면 원인을 확인할 수 있도록 중단합니다.

다음 정답 박스 확인 셀도 실행합니다.

```python
lab.show_labels()
```

초록 박스가 실제 사람·자동차 등의 위치를 감싸는지 봅니다. 박스가 한쪽으로 크게 치우치거나 이미지 크기와 맞지 않으면 학습 전에 해결해야 합니다. 이미지가 어두워도 정답 박스는 확인할 수 있습니다.

ExDark 좌표는 공식 자료의 `[left, top, width, height]`를 그대로 해석하며, 임의의 `-1` 보정을 넣지 않았습니다. 이미지 밖으로 일부 벗어난 박스는 경계 안으로 잘라내고, 그 내역을 변환 보고서에 기록합니다.

## 9. 2단계: D·E·M 학습 입력 만들기

다음 셀을 실행합니다.

```python
lab.prepare_views()
```

| 입력 묶음 | 만들어지는 이미지 |
|---|---|
| D | 원본을 공통 크기 규칙으로 축소한 이미지 |
| E | 같은 크기 규칙으로 처리한 Zero-DCE++ 보정 이미지 |
| M | 각 이미지의 원본 또는 보정본 중 한 가지를 선택한 1:1 혼합 |

모든 방법은 긴 변 최대 640픽셀의 공통 크기 규칙을 사용합니다. 원본 비율은 유지하며 작은 이미지를 이 단계에서 확대하지 않습니다. YOLO 입력 과정의 크기 조절은 그 뒤에 공통으로 적용됩니다.

M은 이미지 수가 두 배가 되지 않습니다. `full`에서는 세 모델 모두 학습 3,000장·검증 1,800장을 사용합니다. M의 학습 입력은 원본 1,500장·보정본 1,500장이고, 검증 입력도 고정된 1:1 구성입니다. 매 epoch마다 새로 섞는 구현이 아닙니다.

`smoke`에서는 마지막에 **모델별 train 120, val 60**이 표시됩니다.

## 10. 3단계: 작은 D 실험으로 첫 학습 성공 확인

이 단계까지는 `MODE="smoke"`를 유지합니다.

```python
lab.train("D")
```

학습 화면에서 epoch가 1/2, 2/2로 진행되고, 마지막에 D 학습 완료와 `best.pt` 경로가 출력되면 첫 작동 확인이 끝난 것입니다.

작은 데이터 120장으로 2회 학습한 수치를 최종 성능으로 해석하지 마세요. 이 단계의 목적은 **데이터 → 모델 학습 → 저장**이 연결되는지 확인하는 것입니다.

노트북에 작은 D 모델로 이미지 한 장을 확인하는 셀이 있으면 이어서 실행합니다. 이때는 `model_name="D"`를 사용합니다. M은 아직 학습하지 않았습니다.

**오늘 처음 시작했다면 여기까지 성공하는 것을 첫 목표로 잡으면 됩니다.** 작은 실험 E·M까지 돌릴 필요는 없습니다.

첫 설정 셀로 돌아가 다음 한 줄을 바꿉니다.

```python
MODE = "full"
```

다른 값은 처음 계획대로 유지합니다.

```python
RUN_TAG = "v1"
EPOCHS = 30
BATCH = 16

```

이후 **0단계 설정·환경 준비 → 1단계 데이터 준비 → 2단계 학습 입력 준비**를 다시 실행합니다. `lab` 객체가 본 실험 설정으로 새로 만들어져야 합니다.

정상 실행 이름은 다음 형태입니다.

```text

```

작은 실험의 이름에는 `smoke`가 들어가므로 결과가 섞이지 않습니다. 본 실험의 입력 준비에서는 학습 3,000장·검증 1,800장이 표시되는지 확인합니다.

## 12. 3~4단계: 본 실험 D·E·M 학습

`MODE="full"`로 0~2단계를 준비한 다음, 노트북의 **3-1에서 D → 4-1에서 E → 4-2에서 M** 순서로 실행합니다.

```python
lab.train("D")
```

```python
lab.train("E")
```

```python
lab.train("M")
```

한 셀이 끝난 다음 다음 셀을 실행합니다. D를 마치고 그날 작업을 끝낸 뒤, 다음에 E부터 이어서 진행해도 됩니다. 세 모델은 모두 같은 사전학습 YOLO11n에서 시작합니다.

| 학습 | 학습·검증 입력 | 끝나면 생기는 파일 |
|---|---|---|
| D | 원본 | `runs/D/weights/best.pt` |
| E | 항상 보정본 | `runs/E/weights/best.pt` |
| M | 고정된 원본·보정본 1:1 | `runs/M/weights/best.pt` |

`best.pt`는 해당 모델의 검증 성능을 기준으로 선택한 가중치입니다. `last.pt`는 이어서 학습하는 데 사용하는 마지막 체크포인트입니다. 최종 테스트를 보고 `best.pt`를 고르지 않습니다.

학습 시간은 실제 GPU와 데이터 입출력 상태에 따라 달라집니다. 30 epoch를 완료하는 데 걸릴 시간을 미리 확정하지 마세요. 첫 몇 epoch의 시간을 확인하고 진행하면 됩니다.

**D는 30 epoch, E는 10 epoch처럼 제각각 학습한 결과를 같은 조건의 비교로 사용하지 않습니다.** 설정을 바꾸고 싶으면 세 모델의 조건을 함께 맞추고 새로운 실행 이름으로 진행합니다.

## 15. 7단계: 검증 데이터로 기준값 고정

D·E·M 학습과 밝은 이미지 준비가 모두 끝나면 실행합니다.

```python

```

이 단계에서는 **ExDark 검증 300장 + 밝은 COCO 검증 300장**을 사용합니다. 최종 테스트는 아직 사용하지 않습니다.

| 기준값 | 뜻 |
|---:|---|
| 0 | 모든 이미지에서 보정 생략 |
| 30 / 60 / 90 / 120 | 평균 밝기가 해당 값보다 낮을 때만 보정 |
| 256 | 모든 이미지 보정 |

실제 보정 선택의 밝기는 공통 크기 조절 뒤, YOLO의 여백을 붙이기 전에 계산합니다. COCO 표본을 고른 원본 밝기와 측정 시점이 조금 다르다는 점을 기록합니다.

선택 규칙은 다음과 같습니다.

1. M-항상, 즉 기준값 256의 mAP50을 기준으로 삼습니다.
2. 전체·저조도·밝은 그룹의 mAP50 감소가 각각 0.01 이하인지 확인합니다.
3. 조건을 만족한 후보 중 측정한 평균 처리 시간이 가장 짧은 것을 선택합니다.
4. 선택된 기준값과 모델 식별 정보를 `protocol.json`에 저장합니다.

0.01은 0~1 척도에서 **1%p**입니다. “1% 상대 감소”와 다릅니다.

**기준값 0 또는 256이 선택돼도 오류가 아닙니다.** 그 경우 해당 검증 조건에서 무보정 또는 항상 보정이 더 적절하다는 결과입니다. 중간 기준값이 나오도록 결과를 보고 후보를 계속 바꾸지 않습니다.

## 21. 자주 생기는 문제

### GitHub 코드를 못 가져온다

`GITHUB_USER`에는 아이디만 넣었는지, `REPO_NAME`이 정확한지, Public 저장소인지, 업로드를 Commit까지 마쳤는지 확인합니다. 저장소 웹 주소를 새 브라우저 탭에서 열어 `src`와 `notebooks`가 바로 보이는지 확인합니다.

### `No module named src` 또는 파일을 찾지 못한다

GitHub 저장소 맨 위에 `src/`가 있어야 합니다. ZIP 바깥 폴더째 업로드하여 경로가 한 겹 깊어졌는지 확인합니다. 올바르게 고친 후 Colab의 코드 준비 셀부터 다시 실행합니다.

### GPU가 없다고 나온다

**런타임 → 런타임 유형 변경 → GPU**를 확인합니다. 무료 GPU 할당이 안 되는 경우에는 가용성이 회복된 후 진행해야 합니다. CPU로 본 학습을 계속 진행하지 않도록 기본 코드에서 중단합니다.

### `CUDA out of memory`

본 실험 시작 전에 `BATCH=8`로 낮추고 0단계부터 다시 준비합니다. 이미 D를 batch 16으로 완료했다면 E만 batch 8로 바꾸어 같은 조건이라고 보고하지 마세요. batch 8의 새 실행에서 D·E·M 조건을 맞춥니다.

### Google Drive 다운로드 제한 / gdown 오류

아래 공식 공유 링크를 브라우저에서 엽니다.

- [ExDark 이미지 ZIP](https://drive.google.com/file/d/1BHmPgu8EsHoFDDkMGLVoXIlCth2dW6Yx/view)
- [ExDark 라벨 ZIP](https://drive.google.com/file/d/1P3iO3UYn7KoBi5jiUkogJq96N6maZS1i/view)

다운로드한 파일을 각각 `ExDark.zip`, `ExDark_Annno.zip`으로 이름을 맞춥니다. 확장자가 숨겨진 Windows에서는 `.zip.zip`이 되지 않게 확인합니다.

Google Drive에서 다음 폴더를 만들고 두 ZIP을 올립니다.

```text
내 드라이브/lowlight_lab/raw/exdark/
```

Drive 연결이 된 상태에서 `lab.prepare_data()`를 다시 실행하면 해당 ZIP을 Colab으로 복구하여 사용합니다. 이름의 `Annno`에는 `n`이 세 개 들어갑니다.

### 이미지가 0장 / 라벨 누락 / 공식 개수와 다르다

해당 오류에서 멈추고 누락 파일과 ZIP 이름을 확인합니다. 학습량을 줄이거나 누락 이미지를 무시해서 해결하지 않습니다. 실제 손상된 다운로드라면 원자료 ZIP을 다시 받아야 합니다.

### 기준값 0 또는 256이 나왔다

정상적인 선택 결과일 수 있습니다. 검증 성능과 처리 시간 조건에서 중간 기준값이 유리하지 않았다는 뜻입니다. 제안 방식이 항상 이긴다는 결과를 미리 정해 두지 않습니다.

### 그래프가 없거나 `protocol.json`이 없다고 나온다

단계를 건너뛰었는지 확인합니다. 본 실험은 **D·E·M 학습 → 밝은 이미지 준비 → 기준값 확정 → 최종 테스트 → 속도 측정 → 보고서** 순서로 진행합니다.

### Drive 용량이 부족하다

원자료 ZIP·모델·실험 결과를 저장할 여유 공간을 확인합니다. 여유 공간 5GB 이상을 계획의 출발점으로 삼되, 실제 사용량을 확인하면서 관리하세요. Colab 임시 디스크와 Google Drive는 다른 저장 공간입니다.

- D·E·M의 학습 조건이 같은가?
- 검증셋으로 기준값을 정하고 테스트에서 바꾸지 않았는가?
- 전체 처리 시간에 실제 보정이 포함됐는가?
- 전체·저조도·밝은 그룹의 결과를 함께 제시했는가?
- 좋은 사례와 실패 사례를 모두 확인했는가?
- 사용한 GPU, 패키지 버전, seed, 데이터 분할을 기록했는가?
- 공개용 ZIP의 집계 결과를 GitHub에 올렸는가?

학습이 끝나기 전에는 결과 표의 숫자를 채우지 않습니다. 성능이 기대와 달라도 원인을 분석하고 실제 수치를 기록합니다.
